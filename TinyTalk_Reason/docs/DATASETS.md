# TinyTalk Reason 1.1 — реальные данные и проверка намерений

## Что выбрано

| Датасет | Назначение | Как используется здесь |
|---|---|---|
| MASSIVE 1.1, ru-RU | Русские запросы, 60 намерений и разметка параметров | Скачивание, конвертация, обучение отдельной MLP, валидация и тест выполнены |
| CLINC150 | Английские намерения и запросы вне поддерживаемых классов | Конвертер реализован и проверен на искусственной структуре формата; сам корпус пока не прогоняли |
| MultiWOZ 2.2 | Многошаговые английские диалоги и состояние разговора | Кандидат на следующий этап; конвертер и интеграция не реализованы |

Источники:
* MASSIVE: https://github.com/alexa/massive ; https://www.amazon.science/code-and-datasets/massive
* CLINC150: https://github.com/clinc/oos-eval
* MultiWOZ 2.2: https://aclanthology.org/2020.nlp4convai-1.13/

MASSIVE — отдельные запросы, а не последовательности сообщений одного пользователя.
Нельзя склеить произвольные соседние строки и назвать это обучением памяти диалога.
MultiWOZ требует новых областей и обработки английского; это не готовая проверка
русскоязычного прототипа о калориях.

## Два режима в одном проекте

1. `bash start.sh --explain`: прежний движок с контекстом. Теперь он выводит
   понятное название выбранной операции и основание. Обучается на прежнем data.txt.
2. `bash start_intent.sh`: отдельный классификатор 60 намерений на MASSIVE.
   Он использует тот же код MLP, но другой checkpoint. Выдаёт предполагаемую задачу,
   не исполняет её и пока не извлекает значения параметров.

Эти модели не объединены в универсальную систему: нельзя подменить checkpoint
Reason весами MASSIVE и ожидать сохранения прежних намерений. `models/intent.bin`
и `models/massive_ru.bin` разделены намеренно. Следующая интеграция требует схемы
параметров, обработчика неизвестных запросов и явного отображения намерений на
поддержанные операции.

## Воспроизведение

Нужны компилятор C11, Bash и Python 3 для конвертации/отчёта. Python использует
только стандартную библиотеку; пакеты pip не требуются. Инференс — программа на C.

```bash
bash run_massive.sh
bash start_intent.sh
# Или один запрос:
bash start_intent.sh 'выключи свет на кухне'
# Прежние контекстные задачи с пояснением:
bash start.sh --explain
```

`run_massive.sh` скачает официальный архив MASSIVE 1.1 (40 251 390 байт, около
38.4 МиБ), проверит SHA256 и извлечёт только русский JSONL и уведомления лицензии.
При последующих запусках архив берётся из кеша. При изменении содержимого по URL
скрипт остановится с несовпадением checksum, а не примет другую выборку незаметно.
Запросов к серверам во время последующей классификации нет.

SHA256 исходного архива:
`4cba5faa11c71437928e17cb1b9b3d8b8e727e7ea363a3a9a8045e19c0491577`.

Обучение на 11 тысячах примеров расходует существенно больше памяти, чем инференс:
исходный код хранит большой массив обучающих признаков (порядка 180 МБ только
для структур примеров). Поэтому не обещаем обучение на микроконтроллере. Можно
обучить на ПК, затем отдельно переносить и проверять runtime и модель.

## Конвертер

```bash
python3 tools/convert_dataset.py datasets/ru-RU.jsonl datasets/massive_ru --format massive
# Если самостоятельно скачан оригинальный CLINC data_full.json:
python3 tools/convert_dataset.py /path/to/data_full.json datasets/clinc --format clinc
```

Выходные файлы:
* `train.txt` — текст TAB метка; именно этот формат принимает TinyTalk.
* `validation.txt` — отдельная часть для выбора параметров.
* `test.txt` — отложенная проверка.
* `*.jsonl` — те же выбранные записи плюс ID и исходная разметка слотов, если есть.
* `labels.txt` — список меток из обучения.
* `manifest.json` — исходные/сохранённые количества и checksum источника.

Аннотации слотов сохраняются для будущего извлечения параметров. Они не подаются
на вход классификатору и не используются как подсказка при тестировании.
Полный корпус и обученные веса не входят в исходный ZIP; их создают скрипты.
Для обучения другой выборки используйте, например:

```bash
bin/train train datasets/clinc/train.txt models/clinc.bin 40
bin/intent models/clinc.bin predict datasets/clinc/test.txt > results/clinc_predictions.tsv
```

Ограничения унаследованного обучателя: до 20 000 примеров и до 256 классов.
Конвертер отклоняет неизвестные разбиения, пустые части, слишком длинные строки
и метки теста, отсутствующие в обучении. Для CLINC объединяет `oos_*` с
соответствующей частью, не перемешивая train/val/test. Для произвольного JSON с
другой схемой потребуется добавить адаптер, автоматического понимания формата нет.

## Как защищались от утечки

Сохраняются официальные разбиения. Нормализованное совпадение текста (NFKC,
нижний регистр, ё->е, пробелы) удаляется в порядке train, validation, test;
внутри одной части сохраняется первая встретившаяся запись, даже при разных метках.
Не выполняется поиск семантических дубликатов: близкие перефразировки могут остаться.
Удаление повторов меняет официальный benchmark; числа нельзя напрямую сравнивать
с таблицами статьи MASSIVE.

| Часть | Исходно | После удаления повторов |
|---|---:|---:|
| Обучение | 11 514 | 11 000 |
| Валидация | 2 033 | 1874 |
| Тест | 2974 | 2726 |

В обучении 60 меток, в оставшихся validation и test встречаются 59. В отчёте
поэтому приведены два macro-F1: по всем 60 и по присутствующим 59 классам.

40 эпох заданы до чтения результатов test. Порог выбирается только на validation:
максимальное покрытие при точности принятых ответов >=90%, не менее 50 принятых,
по сетке 0..1 с шагом 0.001. Если подходящего порога нет, 1.000001 отключает выдачу
задач. Это эмпирический критерий, а не статистическая гарантия будущего качества.
Порог не обнаруживает все запросы вне области; MASSIVE в этом прогоне не даёт
отдельной проверки out-of-scope.

## Полученный результат (Linux, одна инициализация)

| Показатель на тесте | Значение |
|---|---:|
| Правильная метка без отказов | 2131 / 2726 = 78.17% |
| Macro-F1 по 60 классам | 0.7377 |
| Macro-F1 по присутствующим 59 классам | 0.7502 |
| Порог, выбранный на validation | 0.881 |
| Принято при этом пороге | 2103 / 2726 = 77.15% |
| Точность среди принятых | 89.44% |

Высокий score не исключает ошибку. Пример из теста: «хочу узнать статус яркости
моего экрана» получил `social_post` со score 0.9786, хотя метка корпуса —
`general_quirky`. Другой пример: «здесь слишком грязно приберись» классифицирован
как `audio_volume_down` вместо `iot_cleaning` (score 0.5684, поэтому с выбранным
порогом система попросит уточнить). Ошибки опубликованы, а не исключены из метрик.

В `results/massive/` находятся предсказания, по-классовые метрики, выборка ошибок,
журнал обучения и параметры запуска. Тест не переиспользовался для донастройки.
Показатели одного запуска не являются доверительными интервалами или сравнением
со всеми существующими методами. В отчёте есть только простой majority baseline,
а не полноценный сильный baseline.

ASan/UBSan прогнали все 2726 тестовых строк, предсказания совпали с обычной сборкой.
Проверены также конвертер и прежние контекстные регрессии. macOS не запускалась.

## Что означает текст «Нужно сделать»

`actions.tsv` — написанный человеком словарь: метка -> понятное описание задачи.
Сеть выбирает метку, затем выводится соответствующее описание. Например:

```text
Гипотеза намерения: iot_hue_lightoff
Нужно сделать: выключить освещение
Параметры: не извлечены этим классификатором.
Статус: предложение задачи; действие не выполнялось.
```

Это наблюдаемая интерпретация запроса, а не признак сознания. Система не выдаёт
предположение за выполненное действие. В контекстном режиме `--explain` подпись
операции формируется по фактически выбранному правилу и показывает основания.

## Следующий этап

Обучить и отдельно оценить извлечение слотов (что, где, когда, сколько), используя
сохранённую разметку MASSIVE. Затем связать поддержанные намерения и слоты с памятью
Reason и проверять полные многошаговые диалоги. Включить отрицания, отмены,
противоречия, неизвестные запросы, смену темы и ссылки на прежние объекты.
Для оценки нужна независимая русскоязычная диалоговая выборка, не только наши шаблоны.

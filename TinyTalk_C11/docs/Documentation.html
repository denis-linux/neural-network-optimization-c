1. Что это за программа

TinyTalk — маленькая нейросеть, которая учится выбирать ответ на короткую реплику. Вы показываете ей пары «что написал человек → что нужно ответить». Во время обучения программа меняет числовые коэффициенты — веса. После обучения она использует эти веса, чтобы выбирать ответы.

Вы пишете: привет
Модель отвечает: Привет, как дела?

В текущей версии ответ выбирается целиком из списка изученных фраз. Она не сочиняет предложения по одному слову, не помнит прошлые сообщения и не является маленьким ChatGPT. Это нейросеть-классификатор: каждому варианту ответа соответствует свой класс.

При этом выбор делает именно обученная нейросеть. В коде нет правила если введено «привет», ответить .... Файл data.txt во время обычного разговора не читается: для ответов достаточно исполняемой программы и сохранённой модели.

Проект написан на C11. Обучение начинается со случайных весов; никаких готовых нейросетей скачивать не нужно. Bash-скрипты помогают собрать программу, обучить её, сохранить версии и проверить ответы.

Если вам нужен только запуск: прочитайте разделы 2–5. Разделы 6–9 объясняют обучение, 10–12 — исходный код, 13–16 — тестирование и решение проблем.

2. Первый запуск: три команды

Распакуйте TinyTalk_C11.zip. Откройте терминал и перейдите в папку проекта. Путь с пробелами заключайте в кавычки.

cd "/путь/к/TinyTalk_C11"
bash start_learning.sh
bash start_E.sh
bash chat.sh

Выполняйте команды по очереди. Первая обучает и сохраняет модель, вторая проверяет ответы, третья открывает диалог.

КомандаЧто произойдёт
bash start_learning.shЕсли моделей ещё нет, создаст первую со случайными весами и обучит её. Если модель уже есть — продолжит её обучение в новой версии.
bash start_E.shПокажет вопросы, ожидаемые ответы, фактические ответы и PASS/FAIL. Проверки могут выявить ошибки модели.
bash chat.shОткроет разговор в терминале. Напишите реплику и нажмите Enter. Для выхода введите /quit.

Нужен компилятор GCC или Clang и Bash. В Linux они могут быть уже установлены. На Intel Mac, если компилятора нет, установите инструменты разработчика командой xcode-select --install. Python и библиотеки машинного обучения не требуются. Linux проверен в нашем опыте; macOS в нём не запускалась.

Скрипт сборки использует команду cc. При необходимости можно выбрать компилятор: CC=clang bash start_learning.sh. Команда bash перед именем скрипта позволяет запускать его без настройки права исполнения.

4. Как подготовить свои данные

Каждая строка содержит реплику и нужный ответ, разделённые одним настоящим символом табуляции TAB. Файл должен быть в UTF-8.

привет	Привет, как дела?
здравствуй	Привет, как дела?
как дела	Всё хорошо, спасибо! А у тебя?

В примере между полями находится TAB. Не заменяйте его пробелами и не вписывайте буквальную последовательность \t в редакторе. Строки, начинающиеся с #, — комментарии.

Если хотите, чтобы разные вопросы приводили к одному ответу, повторяйте одинаковый текст ответа. «Привет!» и «Привет.» считаются двумя разными классами. Скрипт не допускает назначения двух разных ответов одной и той же исходной реплике.

В исходном корпусе 324 формулировки и ещё 324 варианта с добавлением слова «слушай». Поэтому 648 строк не означают 648 совершенно независимых ситуаций. Это небольшой учебный корпус.

Как добавить новые знания: допишите пары в data.txt и снова запустите обучение либо создайте дополнительный файл.

EPOCHS=60 bash start_learning.sh --resume extra_data.txt

Скрипт объединит старую обучающую выборку, актуальный data.txt и дополнительный файл; точные дубли строк удалит. Старые примеры нужны, чтобы напоминать модели ранее изученные ответы. Это снижает риск забывания, но не гарантирует сохранение качества.

Изменение старого ответа: простое удаление строки из data.txt не удалит её из истории предыдущей модели. Если нужно заменить прежний ответ, исправьте основной файл и начните новую независимую модель через --fresh. Старые версии сохранятся.

Полезные примеры должны отличаться по формулировке: «как тебя зовут», «назови своё имя», «как к тебе обращаться». Многократное копирование одной строки не добавляет разнообразия. Следите за отрицаниями и не смешивайте разные намерения в одной метке случайно.

5. Обучение, дообучение и четыре версии

Обучение с нуля создаёт новые случайные веса. Дообучение загружает уже полученные веса и продолжает их изменять. Версия — отдельная папка с результатом одного завершённого запуска.

# Если моделей ещё нет: v0001
bash start_learning.sh

# Добавляем новый ответ: v0002
EPOCHS=60 bash start_learning.sh --resume extra_data.txt

# Продолжаем: v0003 и v0004
EPOCHS=40 bash start_learning.sh --resume
EPOCHS=40 bash start_learning.sh --resume

# Проверяем четвёртую версию
bash start_E.sh v0004
bash chat.sh v0004

# Сравниваем все версии на одном вопросе
bash compare_versions.sh "какой твой любимый цвет"

Если раньше уже были сохранены версии, номера будут следующими свободными, а не обязательно v0001–v0004. Без явного номера чат и проверка используют запись из models/latest.txt.

ПараметрЗначение
--freshНовая независимая модель со случайными весами. Старые папки не перезаписываются.
--resumeПродолжить последнюю модель; если её нет, сообщить об ошибке.
Без флагаПервое обучение при отсутствии модели; продолжение последней при её наличии.
EPOCHS=60Выполнить 60 дополнительных проходов по всей выборке. По умолчанию — 160.
extra_data.txtНеобязательный дополнительный файл, который будет включён в выборку.

В каждой папке версии находятся:

  • model.bin — веса, ответы и служебное состояние.
  • training.tsv — фактически использованные данные.
  • train.log — журнал обучения.
  • parent.txt — имя предыдущей модели либо none для обучения с нуля.

Для приведённого примера суммарное число эпох: 160 → 220 → 260 → 300. Эпоха — один проход по всем примерам, а не одна секунда и не один вопрос. Номера версий и количество эпох — разные вещи.

Повторное обучение без новых данных всё равно меняет веса. Оно не добавляет новые темы автоматически. Чтобы появилась новая фраза ответа, она должна присутствовать в обучающих данных.

6. Как программа отвечает: пошаговая схема

При ответе веса не меняются. Функция features() только рассчитывает признаки, а forward() применяет уже сохранённые коэффициенты. Ошибка в чате не исправляет модель автоматически: правильный пример нужно добавить в данные и выполнить дообучение.

После каждого сообщения программа начинает новую классификацию. Реплики «Меня зовут Денис» и «Как меня зовут?» не связываются памятью диалога. Если модель выдаёт имя, оно могло быть частью заранее обученного ответа.

7. Как текст превращается в числа

Этим занимается features(). Для русских и английских букв регистр приводится к нижнему, «ё» заменяется на «е». Знаки, которые не относятся к поддерживаемым буквам и цифрам, превращаются в пробелы. Повторные пробелы схлопываются.

Затем выделяются целые слова и короткие фрагменты. Например, из «привет» получаются «пр», «ри», «ив», «ве», «ет», «при», «рив», «прив» и другие фрагменты длиной до четырёх символов. В коде символьные фрагменты могут включать и пробелы между словами.

Каждый признак хешируется — вычисляемый номер определяет одну из 2048 ячеек. В ячейках суммируются счётчики: фрагмент добавляет 1, целое слово — 3. После этого весь вектор делится на его длину, чтобы очень длинный запрос не получал больший масштаб только из-за длины.

Представьте 2048 подписанных номерами коробочек. Каждый фрагмент кладёт отметку в свою коробочку. По полученному набору отметок нейросеть учится выбирать ответ.

Эта часть не обучается. Обучаются веса, которые обрабатывают полученные числа. Новое слово можно обработать без перестройки словаря, но разные признаки иногда попадают в одну ячейку: это хеш-коллизии.

Короткие фрагменты помогают узнавать похожее написание. Полное понимание порядка слов и смысла из этого не следует: далеко расположенные слова и отрицания могут интерпретироваться неверно.

8. Нейросеть без сложных терминов

Внутри два обучаемых слоя. Каждый нейрон берёт входные числа, умножает их на свои коэффициенты и складывает. Например, для входа [2, 4] и коэффициентов [3, −1] получается 3×2 − 1×4 = 2. Эти коэффициенты и есть веса.

Первый слой содержит 48 нейронов. К каждой сумме добавляется смещение — отдельное обучаемое число. Затем применяется tanh, нелинейная функция с результатом от −1 до 1. Второй слой превращает 48 полученных значений в оценки ответов.

В исходной модели 40 выходов, потому что есть 40 ответов. После добавления любимого цвета становится 41 выход. Победивший выход указывает, какую строку напечатать.

h = tanh(W1 × x + b1)
z = W2 × h + b2
p = softmax(z)
ответ = answer[номер наибольшего p]
ОбозначениеПростой смысл
xВходные числовые признаки текста.
W1, W2Таблицы выученных коэффициентов.
b1, b2Выученные добавки — смещения.
h48 внутренних значений скрытого слоя.
zОценки ответов до нормирования.
pОценки softmax, сумма которых равна 1.

Softmax выделяет более высокие оценки и приводит их к общему масштабу. При вычислении программа вычитает максимальную оценку перед экспонентой, чтобы избежать слишком больших чисел.

score 0.98 не означает «98% гарантии правильности». Это относительная оценка среди известных ответов. Даже на совершенно незнакомый вопрос модель вынуждена выбрать один из них и может ошибиться с высоким score.

Для 40 ответов в модели 100312 обучаемых чисел: веса и смещения двух слоёв. Это намного проще трансформера: здесь нет внимания, KV-кэша и последовательного предсказания следующего токена.

9. Как происходит обучение

До обучения веса случайны, поэтому ответы ещё не имеют полезной связи с вопросами. После каждого примера алгоритм изменяет коэффициенты так, чтобы повысить оценку правильного ответа. Повторение многих примеров создаёт эту связь.

Ошибка называется перекрёстной энтропией: loss = −log(p правильного ответа). Если нужный ответ получил маленькую оценку, ошибка велика. Если большую — мала. В коде маленькое ограничение снизу защищает логарифм от нуля.

Обратное распространение вычисляет, как каждый вес влияет на ошибку. SGD изменяет его по правилу новый вес = старый вес − 0.06 × градиент. Число 0.06 — фиксированная скорость обучения в текущем коде; переменная EPOCHS его не меняет.

В начале каждой эпохи примеры перемешиваются. Сохраняются веса, счётчик эпох и состояние генератора псевдослучайных чисел. Используется SGD без momentum, поэтому отдельных накопленных моментов оптимизатора нет. Возобновление не обещает побитового совпадения с одним непрерывным запуском на суммарное число эпох.

Журнал online_train_accuracy считает правильные ответы по мере прохождения обучающих примеров, когда веса ещё меняются. Это не результат независимого теста финальной модели. Даже 100% в этом журнале не гарантируют правильность новых запросов.

Программа ограничивает число обучающих примеров значением 20000. Обработка входа ограничена буфером на 1024 нормализованных кодовых точки. Для надёжных результатов используйте короткие реплики и корректный UTF-8.

read_line(f, line)Читает строку из файла или терминала и проверяет переполнение буфера.Чтение данных и интерактивного ввода.
main(argc, argv)Разбирает команду, создаёт/загружает модель и выполняет нужную ветвь. Здесь же реализован цикл обратного распространения и обновления весов.Точка входа программы.

Где находится обучение? В ветви train функции main(), внутри циклов по эпохам и примерам. Отдельной функции backprop() в этой версии нет.

Где находится «понимание» запроса? В связке features() и forward(). Первая создаёт признаки, вторая выдаёт обученное предсказание. Само по себе разбиение строки на фрагменты не распознаёт намерение.

Где находится выбор готовой фразы? В обращении m->answer[best]. Нейросеть возвращает номер, после чего программа печатает соответствующий текст.

12. Что делают Bash-скрипты и режимы программы

build.sh переходит в папку проекта, проверяет компилятор и запускает сборку с -std=c11 -O2 -pedantic. Параметр -lm подключает математические функции tanh, exp, sqrt и log.

start_learning.sh сначала собирает программу. Затем ставит блокировку обучения, выбирает предыдущую модель и новую свободную папку версии, формирует выборку, удаляет дубли и проверяет противоречия. После успешного обучения сохраняет имя предка и переключает latest.txt. При сбое новая папка может остаться незавершённой, но указатель на последнюю модель не обновится.

start_E.sh выбирает модель, создаёт временный файл шести встроенных тестов и запускает режим eval для него и двух основных наборов. При наличии EXTRA_TESTS проверяет ещё один файл. Пишет отчёты и возвращает 1 при любой неудачной проверке. Временный файл удаляется при выходе.

chat.sh собирает программу, выбирает версию и запускает режим chat. compare_versions.sh перебирает файлы models/v*/model.bin и задаёт всем один вопрос. Эти операции не обучают модель.

test_workflow.sh копирует проект во временную папку, обучает четыре версии и проверяет старые/новые ответы и неизменность v1. Рабочие модели пользователя не изменяет; временная папка удаляется после завершения.

Все обёртки начинают с перехода в свою папку. Относительный путь к дополнительному файлу поэтому считается от папки проекта, даже если вы вызвали скрипт из другого места. Для внешних данных используйте абсолютный путь.

Исполняемую программу можно вызвать напрямую:

./bin/tiny ask models/v0001/model.bin "привет"
./bin/tiny chat models/v0001/model.bin
./bin/tiny eval models/v0001/model.bin tests_seen.tsv
Режим C-программыАргументы и действие
trainDATA OUT EPOCHS [PREVIOUS]: данные, выходной файл, число эпох, необязательная предыдущая модель.
askMODEL TEXT: один запрос, одна строка ответа без score.
chatMODEL: читать реплики до /quit или конца ввода; показывать ответ и score.
evalMODEL TESTS: сравнить ответы с ожидаемыми, напечатать PASS/FAIL и итог.
Прямой train не создаёт версии, не объединяет старые данные и может перезаписать указанный OUT. Для повседневного использования удобнее и безопаснее start_learning.sh.

13. Как понять, что модель обучилась

Есть три разных проверки, и их нельзя смешивать.

ПроверкаНа какой вопрос отвечает
Loss и online_train_accuracy в train.logУдаётся ли подстраивать веса под обучающие примеры?
tests_seen.tsvВоспроизводит ли сохранённая модель знакомые ответы?
tests_unseen.tsvПереносится ли обучение на другие формулировки из небольшого отдельного набора?

Сравнение в eval точное: полученная строка должна полностью совпасть с ожидаемой, включая регистр и пунктуацию. Если модель вернула другую фразу, но она вам подходит по смыслу, тест всё равно отметит FAIL. В этом проекте множество ответов фиксировано, поэтому такое сравнение удобно, но оно не является общей мерой понимания языка.

EXTRA_TESTS=tests_extra.tsv bash start_E.sh v0002
bash test_workflow.sh

В проверке исходного проекта на Linux получено: 6/6 встроенных тестов, 40/40 знакомых реплик, 23/24 других формулировок. Ошибка на «можешь работать офлайн» сохранена в отчёте. Это результаты предыдущего опыта, а не обещание для любого нового набора данных.

До добавления extra_data.txt модель отвечала на вопрос о любимом цвете фразой о фильме. После дообучения v2, v3 и v4 выдавали «Мой любимый цвет — синий.». Это показывает приобретение нового класса ответа; предпочтения у программы от этого не появляются.

Функциональные сценарии ранее проверялись с AddressSanitizer и UBSan. Проверка утечек LeakSanitizer не была доступна из-за ограничения среды. Документация описывает эти проверки, но не заменяет тестирование после ваших изменений.

14. Что сохраняется и как перенести модель

model.bin содержит заголовок формата, размеры слоёв, тексты ответов, веса и смещения, число эпох и состояние RNG. В модели нет копии всего списка вопросов; строки ответов сохраняются как метки классов.

Для ответов на другом совместимом компьютере нужны исходники/собранная программа и model.bin. data.txt для режима ask или chat не нужен. Для продолжения через Bash-скрипт лучше переносить папку проекта целиком вместе с models/: скрипту нужны и модель, и сохранённая training.tsv.

Текущий формат использует обычную двоичную запись int и float. Он рассчитан на совместимые архитектуры с 32-битными int/float и одинаковым порядком байтов. Типичные Linux x86_64 и Intel Mac соответствуют этой схеме, но перенос на все платформы не проверялся. Сам бинарник bin/tiny надо собирать заново под другую ОС.

Пересборка программы не является переобучением. Если вы не меняли структуру модели, сохранённые веса можно загрузить новой сборкой. При изменении F или H потребуется новый совместимый файл модели.

15. Частые вопросы и ошибки

СитуацияЧто проверить
«Сначала запустите обучение»В models/ ещё нет подходящей модели. Выполните bash start_learning.sh.
«Нужен компилятор C»Установите GCC или Clang. Проверьте, что команда cc или выбранная в CC доступна.
«Нужны ровно два поля с TAB»Проверьте разделитель и отсутствие дополнительных табуляций внутри полей. Сохраните файл как UTF-8; предпочтительно с переводами строк LF.
«Противоречащие ответы»В объединённых данных одна исходная реплика имеет два ответа. Исправьте новые примеры; для замены исторических ответов используйте исправленный основной корпус и --fresh.
После дообучения старый ответ осталсяПроверьте версию в latest.txt и что чат запущен с новой моделью. Открытый чат уже загрузил старую модель: завершите его и запустите снова.
«Другое обучение уже запущено»Проверьте работающие процессы. Если обучение точно завершено аварийно, удалите пустую блокировку rmdir models/.training_lock. Не удаляйте её у работающего обучения.
Проверка завершилась с кодом 1Откройте reports/ и найдите FAIL. start_E.sh возвращает 1 и при обычной ошибке предсказания, например на одной новой формулировке.
100% обучения, но плохие ответыВозможно, модель запомнила узкие примеры. Добавляйте разнообразные данные и проверяйте новые формулировки отдельно.
На незнакомый вопрос отвечает уверенноУ модели нет надёжного механизма отказа. Она всегда выбирает один известный ответ; score не решает эту проблему.
Забыла ответ после дообученияПроверьте старые примеры в training.tsv, баланс данных и результаты предыдущей версии. Сохранение старого корпуса снижает риск забывания, но не устраняет его.
Хочу удалить только одну неудачную версиюНе меняйте её предков. Помните, что latest.txt может ссылаться именно на неё; перед ручными изменениями сохраните резервную копию models/.
Почему фраза «поставь таймер» ничего не делаетДанная версия только выводит текст. Исполнителя команд ОС в ней нет.

Коды самой C-программы: 0 — успех; 1 — диагностируемая ошибка; 2 — запуск без команды с выводом справки; 3 — неполное прохождение eval. Большинство ошибочных аргументов обрабатываются через die с кодом 1. Скрипт проверки приводит неуспешные проверки к итоговому коду 1.

16. Ограничения и короткая памятка

Нейросеть не создаёт произвольные новые ответы, не понимает мир в человеческом смысле и не имеет доступа к часам, погоде или вашим файлам. Она распознаёт закономерности в текстовых признаках на основании маленькой обучающей выборки. Сложные запросы, опечатки, отрицания и новые темы могут приводить к ошибкам.

Ответ «Я не знаю ответа» — такой же обучаемый класс, как остальные. Он не превращает модель в надёжный детектор неизвестных вопросов.

Практический цикл: добавили качественные примеры → обучили новую версию → проверили знакомые и новые реплики → сравнили с предыдущей → выбрали подходящую версию для чата.

# Старт
bash start_learning.sh
bash start_E.sh
bash chat.sh

# Добавление данных и новая версия
EPOCHS=60 bash start_learning.sh --resume extra_data.txt

# Сравнение
bash compare_versions.sh "какой твой любимый цвет"

# Независимое обучение с нуля, с сохранением старых версий
bash start_learning.sh --fresh
